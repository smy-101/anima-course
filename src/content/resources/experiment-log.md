PNG 里嵌的工作流能还原“当时怎么连的”。它还原不了“你在对比什么、你觉得哪张更好、为什么”。所以每次实验记一行，一天 10 行。

## 模板

下表复制即用。

| 日期 | 实验 ID | 目的 | 模型 / LoRA（强度） | 提示词（摘要） | seed | 分辨率 | steps | cfg | 采样器 / 调度器 | denoise | 其它变量 | 结论（好 / 坏 / 为什么） | 文件名或目录 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 11-25 | E001 | 找 cfg 甜点 | base-v1.0 | 樱花少女 A | 12345 | 1024² | 30 | 3.5 | euler / simple | 1 | — | 3.5 偏淡，发色特征丢失 | `Anima/E001/00003` |
| | E001 | | | | | | | 4.0 | | | | 4.0 最佳，线条干净、颜色到位 | `Anima/E001/00004` |
| | E001 | | | | | | | 4.5 | | | | 4.5 开始线条发硬 | `Anima/E001/00005` |
| 11-25 | E002 | 采样器风格 | 同上 | 同上 | 12345 | 1024² | 30 | 4.0 | er_sde / simple | 1 | — | 比 euler 更平涂；细节略少 | `Anima/E002/00001` |

不想手抄表，用站内的[实验记录本](/tools/lab-log/)。选变量、填取值，它就生成扫描行；留空的格按“同上”继承。改了两个变量、结论没写为什么，它会直接标出来。导出的 CSV 和 Markdown 用的就是上面这张表的列。

## 记录规则

- **一个实验 ID 对应一次扫描，只改一个变量。** 同一 ID 下其它列不变，只填变化的那一列。
- 结论列必须写“为什么”，不能只写“好”。
- 文件名列用保存图像节点的前缀带实验 ID，比如 `Anima/E001`，表和图就能对上。参数列允许写“见 PNG”，因为把图拖回画布能还原全部参数。目的与结论两列必须手写。
- 每天最后一行写“今日基线”，记下当前认定的最佳组合：模型、采样器、cfg、steps、denoise。第二天的实验从它出发。
- 失败也记。“3.5 发色丢失”是信息，不记就会重复踩。

## 自动对上记录

- `SaveImage.filename_prefix` 支持变量：`%date:yyyy-MM-dd%`、`%节点名.参数%`。设成 `Anima/E001/%KSampler.cfg%` 就自动按 cfg 分目录。
- 用 L2 的创建列表做扫描时，列表顺序就是输出顺序，表里按同一顺序记即可。
- 想全自动化，就用 HTTP API 跑扫描，脚本顺手把参数写进 CSV，做法见[选修 A](/lessons/05-05-elective-api/)。

## 每日复盘

每天收工前花 5 分钟，回答三个问题：

- 今天最佳是哪张，为什么。
- 今天学到的“不要这样做”。
- 明天的实验 ID 和要验证的假设。

答案写进表尾或当天笔记，第二天开工先看它。

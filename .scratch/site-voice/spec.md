# 站点文风与版面打磨

Status: ready-for-human（票 01–11 全部 done；剩作者通读票 03–10 的改写成果，之后是 Out of Scope 里的版面重构 prototype）

> 来源：2026-11-24 的 grill 会话（Q1–Q16 全部按推荐定）。词汇按 `GLOSSARY.md`；遵守 `docs/adr/0001-派生时重写文风.md`。研究依据见 `docs/文风依据.md`（后台研究中，到位后规范引用它）。

## Problem Statement

学习者打开一课，标题在列举内容，标题下的导语再列举一遍，正文开头的「目标」第三遍——滚过三遍目录才见到正文。正文里加粗满屏（全课中位数约每千字 10 处，两篇到 22–23），数字清单化的命名（三种写法、七条硬规则、四段式）、「X：Y」冒号标题、破折号 134 处、箭头 360 处，该是散文的机制解释也做成表。读者的感受是「像机器写的」：读起来累，抓不住哪一句才是不能漏的。

根因不在迁移：`source/` 笔记本身就是这个腔调，站点是它的忠实派生。所以要在派生这一步改写。

版面上还有一批可见缺陷（已修 6 项），以及一批需要看变体才能定的结构问题（本轮不做）。

## Solution

1. 一份《站点文风》契约（`docs/文风.md`，一页以内，每条带本站正反例）：读者称呼、6 条硬规则、7 条软规则、加粗 / 标题 / 导语的约定。
2. 硬规则做成 `prose-lint`，接进 `npm run check:site`，以棘轮方式收紧：没改写的文件只出报告，改过的必须过，最后一张票切成全量硬失败。
3. 按契约把课程（20 篇）、排错（51 篇）、资源（9 篇）整篇派生改写；节点卡（83）和标签卡（340）只跑 lint 修硬规则。先改试点课 `01-03`，用它校准硬规则的终值，再开其余票。
4. 版面本轮只打磨，不改信息结构；结构问题列为后续 prototype 事项。

## User Stories

1. 作为学习者，我希望打开一课只在一处看到这课讲什么，这样不用滚过三遍目录才见正文。
2. 作为学习者，我希望加粗只标出界面上要找的控件名和每节不能漏的那一句，这样扫一眼就知道该点哪里。
3. 作为学习者，我希望标题短、说这课做什么（如「L4 · 放大三路线」），这样在导航和翻页器里一眼能认出来。
4. 作为学习者，我希望机制类的解释是散文而不是表，这样读得顺。
5. 作为学习者，我希望破折号和箭头少一点，这样句子不会一直被打断。
6. 作为学习者，我希望正文末尾不再有和验收清单、翻页器重复的「验收」节，这样不会疑惑哪一个是正式的。
7. 作为学习者，我希望验收清单仍是唯一的进度入口，这样勾选不会混乱。
8. 作为学习者，我希望窄屏上表格横向滚动而不是把代码拆成五行，这样能在手机上读陷阱标签表。
9. 作为学习者，我希望右侧目录的长标题能看全或至少有省略号，这样知道点进去是哪一节。
10. 作为学习者，我希望首页 hero 没有线穿过导语、路线图说明不出现一字孤行，这样第一屏看起来是对的。
11. 作为学习者，我希望待补图占位不抢眼，这样注意力落在正文上。
12. 作为学习者，我希望正文人称统一用「你」，这样不会被「我们」和无人称来回切换打断。
13. 作为作者，我希望文风规范一页以内、每条带本站正反例，这样改写时有据可依而不是凭感觉。
14. 作为作者，我希望硬规则能被脚本检查并进 `npm run check:site`，这样改坏了自己会知道。
15. 作为作者，我希望 lint 是棘轮，这样无关改动的四项收尾不被卡住。
16. 作为作者，我希望规范里的数值在试点课上校准后再定终值，这样数字有依据。
17. 作为作者，我希望 `source/` 笔记保持原样，这样一手资料不被改写覆盖，随时能对照回溯。
18. 作为作者，我希望有一条 ADR 记下「派生时重写文风」，这样以后看到站点和笔记措辞不同不会以为是改错了。
19. 作为实现代理，我希望每张票都引用规范和 ADR，这样不用自己发明「什么叫不 AI」。
20. 作为实现代理，我希望试点课先改完并作为样板可对照，这样后续 19 课有成品可看。
21. 作为实现代理，我希望字典卡只跑 lint 不重写，这样 400 多张卡不会吞掉整个窗口。
22. 作为未来的贡献者，我希望文风依据文档列出每条规则的一手来源和支持强度，这样能判断哪条规则可以挑战。
23. 作为未来的贡献者，我希望 `GLOSSARY.md` 定义了「硬规则 / 软规则 / 导语 / 三连目录」，这样讨论时不用反复解释。
24. 作为作者，我希望版面重构的问题被明确列为后续事项，这样不会被遗忘也不会混进这一轮。
25. 作为学习者，我希望引号全站一个体例、句子不超过 40 字，这样不会在同一页里看到两种引号、不用回读长句。

## Implementation Decisions

**《站点文风》文档**
- 结构：读者称呼 → 硬规则（6 条，各带数值与正反例）→ 软规则（7 条）→ 加粗 / 标题 / 导语三条约定。一页以内。
- 读者称呼统一「你」。
- 硬规则（暂行值，试点课后定终值）：
  1. 无三连目录：课程正文不得出现「## 目标」小节；导语只说「学完你能做什么」。
  2. 加粗密度 ≤ 4 处 / 千字。加粗只给两类东西：界面上的控件 / 节点名，和每节里那一条不能漏的话。
  3. 标题 ≤ 20 字（去掉「L4 · 」类路径前缀后计）。
  4. 导语 ≤ 70 字。
  5. 正文小节不得与固定区块重名（验收清单、对照图、本课涉及、翻页器）。
  6. 引号一律用 “ ”：代码跨度之外的正文与 frontmatter 字符串值里不得有 ASCII 直引号 `"`（clreq、GB/T 15834、排版指北一致）。
- 软规则：数字清单化命名；「X：Y」冒号标题与括号标题；破折号与箭头密度；口诀 / 俏皮话；表格反射；标题不列举内容；一句一个意思，超过 40 字拆句。
- 每条规则旁注 `docs/文风依据.md` 里的来源编号；依据文档到位后补齐。

**prose-lint 规则模块**
- 纯函数：输入 frontmatter（对象）+ 正文（markdown 字符串）+ 集合名，输出违规列表（规则 id、严重度、位置、说明）。形制与 prompt-lint 一致。
- 计数口径：加粗只数正文 `**…**`，代码块与行内代码内不计，一对算一处；字数按 CJK 字符数。导语长度按 `summary` 字符数。标题长度按去掉路径前缀后的字符数（含空格、英文与标点）。引号规则查代码跨度之外的正文，以及按 YAML 解析后的 frontmatter 字符串值（解析后 `\"` 已是 `"`）。
- 固定区块重名检查只对课程集合生效。

**接入构建后检查**
- 脚本跑在 lessons / troubleshooting / resources 三个集合；nodes / tags 只跑加粗与引号两条。
- 棘轮：默认报告模式；一份「已改写」名单里的文件必须全部通过，否则退出码 1；名单里写了仓库里不存在的条目也退出码 1（防拼错后名单形同虚设）。最后一张票把名单换成全量硬失败。报告落到 `reports/`（已被 gitignore）。

**内容改写**
- 「## 验收」节在全部 20 课删除；其中独有的操作提示并入验收清单条目或正文对应小节；「下一课」链接由翻页器承担。
- 试点课 `01-03-prompt-basics`：整篇派生改写 → 跑 lint → 作者通读 → 校准硬规则终值 → 更新规范。它是后续票的样板。
- 其余 19 课、排错 51 篇、资源 9 篇：整篇派生改写，软规则也过。`source/` 不动。
- 节点卡、标签卡：只修 lint 报出的加粗与直引号。

**版面**
- 本轮只打磨。已修 6 项：hero 连接线定位、目录截断、占位块重复说明与降权、路线图说明孤行、窄屏表格滚动、单元格最小宽度。

## Testing Decisions

- 好的测试只测外部行为：给一段 markdown，断言 lint 报出 / 不报出某条规则；不测内部函数。
- 模块：prose-lint 规则模块——`node --test` 用例，fixture 字符串覆盖每条规则的命中与豁免（代码块内加粗不计、路径前缀不计入标题长度、非课程集合不查固定区块重名、代码跨度内的直引号不计、frontmatter 外层 YAML 引号不计）。先例：prompt-lint 的测试。
- 集成：`npm run check:site` 跑一次，断言报告模式退出码 0、名单内违规退出码 1（票 11 起名单退场：任一集合一处违规即退出码 1）。先例：死链退出码。
- 软规则不写测试。改写后的课以 lint 全绿 + 作者通读为验收。

## Out of Scope

- `source/` 的任何修改。
- 节点卡、标签卡的整篇重写。
- 成人附录（`nsfw` 集合）：本轮不动；以后触及时按同一规范。
- 补图、提示词检查器规则、课程内容的事实性修订。

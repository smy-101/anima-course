## 1. 定位

以 Anima × ComfyUI 为载体，教"AI 生图的一般方法"的循序渐进课程站。

- 教的不是参数，是方法：固定种子、一次只改一个变量、Turbo 试稿 / Base 出成品、固定分辨率
- 所有数值标为**起点值**而非推荐值；练习的目的是让学习者自己验证
- 受众：零基础但会用电脑，8GB+ 显存 N 卡（或云）
- 终点：14 天后能独立搭出"文生图 → 放大 → 重绘"流水线
- 扩散、采样、CFG、LoRA、结构控制、放大、重绘都是通用概念，Anima 只是具体模型

## 2. 设计原则

1. **教方法不教参数**——每个参数值旁边写"这是起点，用固定种子验证"。
2. **课程与参考分离**——课程页只放"这一级需要知道的"，细节链到参考层；参考层每个条目反向链回首次出现的课。
3. **只留一条路径**——把 14 天工作流路径与 7 天提示词路径合并为一条双轨路径，删掉三张路径对照表。
4. **可信度可见**——每条结论带来源徽章（官方 / 源码 / 作者 / 平台 / 社区 / Danbooru），每页带核实日期。
5. **实验有记录**——验收清单与实验记录本是一等功能，不是附属品。

## 5. 成人附录（NSFW）

### 5.1 政策依据（GitHub）

GitHub《Sexually Obscene Content》禁止"目的只在引起情色或震惊反应"的内容，明确包括 *"Graphic depictions of sexual acts including photographs, video, animation, drawings, computer-generated images, or text-based content"*；同页写明 *"We may allow visual and/or textual depictions in artistic, educational, historical or journalistic contexts… a disclaimer can help communicate the context… we may choose to limit the content by giving users the option to opt in before viewing."* GitHub Pages limits 页引用同一限制。

结论：本站的 NSFW 部分是**词典式文字**（标签含义，释义源自 Danbooru wiki），属教育语境。按 GitHub 自己描述的处理方式做：**可选择加入 + 免责声明 + 不含图片**。残余风险是 GitHub 仍可依举报处理，所以必须有构建开关。

### 5.2 结构

- 独立集合 `src/content/nsfw/`，路由前缀 `/nsfw/`
- 构建开关 `NSFW=true|false`；关闭时整个集合不构建、导航不出现
- 年龄确认页（18+ 勾选 → localStorage）；未确认访问 `/nsfw/*` 一律跳回确认页
- 默认不进搜索索引（`data-pagefind-ignore`）、`<meta name="robots" content="noindex">`、不进 sitemap
- 课程页不放直达链接，只放一行"成人内容见附录（需确认）"
- 每页顶部固定声明：教育 / 词典用途；释义来源；不含图片

### 5.3 内容范围

- 收录：提示词报告 §4（安全等级与打码规则）、§5 词表、§6 负向中的相关项、§7 陷阱、§10 模板 B–F
- 同时进主线的只有：安全等级四选一、SFW 用户必须写 `safe`、"等级与画面不匹配会发软 / 自动打码"的原因（§0、§4.1–4.2）
- 沿用原文的处理：§5.10 极端标签"仅列出供识别、不提供用法"；§12 合规与风险提示保留并前置
- **露骨示例图不放在 GitHub Pages**——后补图时只给主线补图，附录保持纯文字

## 6. 内容模型

六个集合（Astro Content Collections），都是带 frontmatter 的 Markdown，由 `glob` loader 载入；frontmatter 有类型检查，迁移时批量暴露缺字段。完整 schema 以 `src/content.config.ts` 为准（字段含义写在那里的注释里），下面只列形态和关键字段：

| 集合 | id 规则 | 关键字段 |
|---|---|---|
| `lessons` | 文件名 | `stage` / `order` / `summary`（导语）/ `levels` / `days` / `promptTrack` / `elective`（选修，不计入 14 天）/ `prerequisites` / `nodes` / `tags` / `deliverable` / `acceptance` / `figures[{ id, src?, caption, group? }]` / `transfers` |
| `nodes` | 文件名 = 英文类名，保留大小写 | `name_zh` / `category` / `first_level` / `experimental` / `inputs[]` / `outputs[]` / `params[]` |
| `tags` | 文件名 = 小写连字符 slug | `tag` / `meaning` / `category` / `polarity` / `trap` / `versions{ base?, aesthetic?, turbo? }` / `wiki` |
| `troubleshooting` | 文件名 | `symptom` / `area` / `first` / `then` / `dont` |
| `nsfw` | 文件名 | `title` / `section` / `order` |
| `resources` | 文件名 | `title` / `kind`（模型文件 / 工具 / 链接 / 模板 / 误区 / 基线 / 概念）/ `order` |

共有字段：`sources[{ badge, url?, note? }]`（badge 只能是 官方 / 源码 / 作者 / 平台 / 社区 / Danbooru）和 `verified`（`YYYY-MM-DD`）。

- `misconception`（误区）并入 `resources`，自测题从 `kind: '误区'` 的条目生成。
- 节点 × 级别矩阵（递进报告附录 A）由 `nodes.first_level` 自动生成，不再手写。

### 7.1 补图脚本（2026-11-27 起）

图由脚本固定种子生成，权重用官方的 `anima-base-v1.0` / `anima-aesthetic-v1.1` / 官方 LoRA / LLLite（已补 54 张对照图；另有 9 张界面截图，见下面的 `screenshots.mjs`）；仍占位的 13 张：8 张等插件或角色 LoRA，4 张在两版权重上都没复现课程说法（标签传染、eye contact 标签优势、NAG、路线 A 在背景里加物件）。缺的模型用 `download_models.py` 从 Hugging Face 下到 Windows 的 models 目录：

- `scripts/figures/figures.py`：按组出图（`setup l0 pb l2 pm l3 l4 l6 l7 l8 l7-composite`），固定种子写在文件顶部（基线 `SEED = 42`，种子组 11 / 88 / 23），提示词用 `resources/prompt-templates.md` 的模板 A / B / C / D。输出到 `figures-out/<id>/`（git-ignored），每张图附带提交过的 `.api.json`，`manifest.json` 记 prompt_id 与耗时。
- `scripts/figures/comfy_client.py`：WSL 直连 `127.0.0.1:8188` 的最小客户端（`http.client`，不经代理），API 格式工作流的拼装工具也在里面。
- `scripts/figures/prepare-site.mjs`：PNG → `src/assets/figures/<id>.webp`（长边 ≤ 1600），并把 `src` 写进 frontmatter；图与课程的对应关系在文件顶部的 `MAP`。
- `scripts/figures/to_workflow.py --all`：把出图用的工作流转成前端格式，放 `public/workflows/`；`embed_workflow.py` 把它嵌进 PNG 的 `workflow` 块，拖回画布即可还原。
- 课程正文按官方模板写 `anima-base-v1.0`，图也用它出；最早一批 preview3 权重的图留在 `figures-out-preview3/`（不入库），可删。
- 每张 PNG 原图都嵌了它自己的前端格式工作流（`embed_workflow.py`，由同目录的 `.api.json` 转换而来），拖回画布还原的就是出这张图的那条工作流；`public/workflows/` 里是按级别整理的九个样例（L0–L8）。原图打成 `figures-out/anima-course-figures-originals.zip` 上传 Releases，文件名即图 id（已传：Release `figures-v1`；站内入口在 `/resources/workflows/` 和每课的对照图说明里，链接用 `releases/latest/download/…`，以后补图传成新的正式 Release 即可）。
- `scripts/figures/screenshots.mjs`（2026-11-28 起）：界面截图。用 Windows 上的 Chrome 无头模式打开本机 ComfyUI 前端，走 DevTools Protocol 操控页面，在页面里用前端自己的接口摆画面：`app.loadGraphData` 载入工作流、`unpackSubgraph` / `openSubgraph` 展开或进入子图、"发布子图"进节点库，再按节点包围盒裁剪、叠标注。输出到 `figures-out/screens/`，按 2 倍分辨率存（`prepare-site.mjs` 的 MAP 里给 `edge`），画廊里点开看原尺寸。它只用页面里的样式藏掉挡画布的面板，不点界面上的开关：那些开关会把设置写到服务端的 `comfy.settings.json`，连带改掉 Desktop 的界面。要在 Comfy Desktop 自己的窗口里截（Desktop 带着的外壳、和浏览器不同的地方），Desktop 用 `--remote-debugging-port=<端口>` 启动后 `DESKTOP_CDP=<端口>` 运行，脚本只关自己新开的标签页，拍完恢复窗口。实测下来 Desktop 和浏览器的界面几乎一样，差别只在 Desktop 的安装器界面；“问题”页里并没有一键下载按钮（Desktop 内置的 Manager 不暴露接口），课程 00-01 的说法已按实际界面改。

## 9. 技术选型

**Astro + MDX + Content Collections**，理由都对应本项目的具体需要：

| 需要 | Astro 怎么满足 | VitePress 的差距 |
|---|---|---|
| 六种内容类型、frontmatter 校验 | Content Collections + Zod schema，构建时校验 | 需自行约定，无类型检查 |
| NSFW 构建开关、待补图清单 | 环境变量 + 构建钩子 | 需绕路实现 |
| 提示词检查器 / 实验记录本 / 年龄确认 | Islands，React / Svelte 按需加载 | 只能 Vue |
| 40–60 张对照图 | `astro:assets` 自动生成多尺寸 WebP / AVIF | 无一等公民的图片管线 |
| 中文搜索 | Pagefind v1.5+ 自动 CJK 分词，静态索引 | 内置搜索对中文需额外配置 |

部署：`.github/workflows/deploy.yml` → `withastro/action` → `actions/deploy-pages`。本机已有 Node 24.19 / npm 11.17（mise）。
